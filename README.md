# Агент проверки ковенантов

Читает корпус кредитных договоров, аудиторских дел и досье KYC, проверяет финансовые ковенанты
каждого заёмщика по леджеру транзакций и показывает выкладку по каждому ответу.

Сделано для Halyk AI Challenge. Инженерная работа велась с Claude.

| | |
|---|---|
| [`submission.json`](submission.json) | сам ответ |
| [`docs/solution.html`](docs/solution.html) | как устроено решение: архитектура, этапы, ограничения |
| [`cache/provenance.ru.html`](cache/provenance.ru.html) | откуда взято каждое число ([English](cache/provenance.html)) |

## Результат на опубликованных данных

**36.00 / 36 — 100.00%.** Верно 36/36 по `status`, 36/36 точно по `actual`, 9/9 по доказательству
(ячейки с непустым ключом). Правил, принятых без опоры на текст документов, только потому что с
ними сходится ключ, — ни одного.

## Главная идея

**Модель решает, что вычислять. Вычисляет — код.** Модель читает пункт договора и возвращает
формулу, знак сравнения и порог — но никогда её не вычисляет. Ни одно число в ответе не получено
языковой моделью.

Граница проведена здесь потому, что две половины ошибаются по-разному. Неверно прочитанный пункт
даёт формулу и процитированный порог, которые проверяющий сверит со страницей за несколько секунд.
Если бы модель ещё и считала, она выдавала бы правдоподобное число, которое не с чем сопоставить.
Подробно — в [`docs/solution.html`](docs/solution.html).

## Как запустить

Нужны Python 3.13 или новее, [`uv`](https://docs.astral.sh/uv/) и ключ Anthropic API с доступом к
`claude-opus-5`. Текст извлекается локальной библиотекой на Rust: OCR-сервиса, векторного хранилища
и внешнего индекса нет.

```bash
uv sync
cp .env.example .env      # впишите сюда ANTHROPIC_API_KEY

# прочитать документы -> cache/facts_extracted.json
uv run python -m covagent.build_facts --workers 6

# собрать, проверить и оценить ответ
uv run python -m covagent.run --facts cache/facts_extracted.json
```

Извлечение кэшируется по хешу содержимого — в него входят текст документа, модель, изображения,
инструкции и схема ответа. Повторный запуск бесплатен и продолжается с места остановки, а правка
промпта обесценивает именно те извлечения, которые этот промпт и породил.

### На другом наборе документов

Все команды принимают `--data` — путь к папке, в которой лежат каталог `documents/`, один файл
`*ledger*.csv` и `submission_template.json`. Леджер находится по образцу имени, а не по точному
названию. Файл `ground_truth.json` необязателен: без ключа прогон записывает ответ и пропускает
оценку. Отсутствие каталога или шаблона останавливает запуск сразу и с указанием пути, вместо того
чтобы записать пустой ответ, который выглядит как успешно завершённый прогон.

```bash
uv run python -m covagent.build_facts --data /путь/к/набору --workers 6
uv run python -m covagent.run --data /путь/к/набору --out submission.json
```

### Проверка без ключа

У скрытого набора ключа нет, то есть балл недоступен именно тогда, когда он нужнее всего. Эти
команды к API не обращаются и работают без него:

```bash
uv run python -m covagent.confidence   # перечень того, что должно быть верно, чтобы ответ был верен
uv run python -m covagent.leakage      # решение не подогнано под опубликованный набор
uv run python -m covagent.perturb      # синонимы, нераскрытая валюта, перемешанные строки, шум
uv run python -m covagent.ablate       # цена каждой части конвейера и лестница уровней
uv run python -m covagent.report --lang ru        # выкладка по всем 36 ячейкам -> HTML
uv run python -m covagent.explain --cell B1:6.1   # то же обычным текстом
```

Отдельно стоит последний способ проверки — прогон на фактах, переписанных вручную:

```bash
uv run python -m covagent.run --facts cache/facts.json
```

`cache/facts.json` переписан из тех же документов человеком, поэтому ошибка на этом прогоне
означает ошибку в арифметике, а не в чтении. Оба набора фактов дают одинаковый ответ по всем
36 ячейкам.

### Уровни

`--level` ограничивает то, что конвейеру позволено знать. Код на каждом уровне побайтово один и
тот же; меняются только факты, поэтому лестница измеряет доказательства, а не реализацию.

| Уровень | Что читает | Балл |
|---|---|---|
| `L1` | Только договор и леджер | 16.00 / 36 |
| `L2` | + условия срабатывания, периоды | 16.00 / 36 |
| `L3` | + связанные стороны из KYC | 25.00 / 36 |
| `L4` | + аудиторские корректировки | 31.00 / 36 |
| `L5` | + показатели из документов, курсы валют | 35.00 / 36 |
| `L6` | + исправления источников (по умолчанию) | 36.00 / 36 |

Больше половины доступных баллов лежит в аудиторской цепочке и досье KYC, а не в тексте ковенанта.

## Что остаётся после прогона

| Файл | Содержимое |
|---|---|
| `submission.json` | Ответ, проверенный на совпадение ключей с шаблоном |
| `cache/derivations.json` | Полная выкладка по каждой ячейке: текст пункта, входные величины, участвующие строки, корректировки с цитатами, вердикт, основание доказательства |
| `cache/facts_extracted.json` | То, что прочитала модель, с записанным идентификатором модели и выражением за каждой выведенной величиной |
| `cache/facts.json` | Набор фактов, переписанный вручную |
| `cache/source_corrections.json` | Исправления от владельца данных к числам, напечатанным в документах неверно |

Журнал разработки и разбор ошибок — в [`tasks/findings.md`](tasks/findings.md) и
[`tasks/todo.md`](tasks/todo.md) (на английском).
